# Relational Model vs Document Model

## Key Points

### The Birth of NoSQL
- **NoSQL** stands for "Not Only SQL"
- Emerged from need for horizontal scaling, open-source, and schema flexibility
- Not a replacement for relational databases

### Object-Relational Mismatch
- Application objects don't map cleanly to relational tables
- Need for object-relational mapping (ORM)
- Document model reduces this mismatch

### Many-to-One Relationships
- Relational databases handle these naturally
- Document databases can embed or reference
- Each approach has tradeoffs

### Many-to-Many Relationships
- Relational databases use join tables
- Document databases embed or reference
- Performance implications of each approach

### Are Document Databases Repeating History?
- Hierarchical databases (1960s-70s)
- Network model (CODASYL)
- Relational model solved hierarchical limitations
- Document model has similar limitations

### Relational vs Document Databases Today
- Both have their place
- Polyglot persistence is common
- Choose based on workload characteristics
